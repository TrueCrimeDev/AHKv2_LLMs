# The Grading Graph: One Rule, Four Tiers, and 47 Scripts That Quietly Did Nothing

<style>
.d-narrow{display:none}
@media (max-width:680px){.d-wide{display:none}.d-narrow{display:block}}
</style>

Every benchmark here ends with a model emitting an `.ahk` file and something deciding whether it is any good. That something is now a dependency graph: four gated tiers, one result contract, and a checker whose only job is discarding evidence it cannot trust. Across the 159 [AHK-Eval](post.html?slug=ahk-eval-benchmark) submissions it found 49 that will not load — and **47 that load perfectly, run cleanly, and do nothing at all**.

One rule shapes it: there is only one desktop, so the tier that types and clicks for real runs serially. Everything else fans out.

## The Tier That Cannot Fan Out

Tier 4 is the only one that touches the desktop, which is why it is the only serial one. Tier 3 gets the same scripts *executed* without that constraint, by exploiting an AHK property that turns out to be load-bearing: **a user-defined function shadows the built-in of the same name, and the shadow reaches across `#Include`.** A generated wrapper includes a shim and then the candidate, so the candidate's `Send`, `Click`, `WinActivate`, `FileDelete` and `RegWrite` record what they were asked to do instead of doing it. The script runs for real. Only its effects on the outside world are intercepted.

The deadline is deliberately *not* enforced inside the script. A pending AHK timer is itself a reason for the process to stay alive, so an in-script watchdog keeps every candidate running to the deadline and makes a script that finished cleanly indistinguishable from a persistent one. Instead the runner waits from outside and, when the deadline passes, sends the script's hidden message window a `WM_NULL`. An idle hotkey script answers immediately; one wedged in a blocking call cannot answer at all. That single probe is the difference between exit 124 (idle — a pass, because staying resident is the job) and exit 137 (wedged — a failure).

Three cases were worth encoding:

**The grammar gap.** The bundled `tree-sitter-ahk.dll` fails on a brace-less `catch` or `finally` body that follows a closing brace. `try { … } catch Error as err` on one line and its handler on the next breaks the parse; the same code with the try body unbraced parses fine. The interpreter accepts every variant. When it triggers, `HasParseError` goes true and *every* Lint and CodeIntel finding in that file is reasoning over a damaged tree — which is how one file drew a confident "code after a return is unreachable" pointing at a reachable line. 36 of 159 scripts hit it. Findings from those files are demoted a rank and marked `partial`.

**The single-file blind spot.** `undefined-call` fires on anything CodeIntel cannot see, which includes every name arriving via `#Include`. It is a lead, not a defect, and it is ranked accordingly.

**The rule that is simply buggy.** `unreachable-code` fires on `for … { if (x) return y }` followed by `return default` — the search-a-collection idiom — on a completely clean parse, because a loop whose body ends in a return is treated as terminal for the block around it. Capped at medium.

## Two Fixes, and What They Moved

Two of those diagnoses turned into fixes in `CodeIntel.ahk`. Classes were never added to the set of callable names, so **every `ClassName()` instantiation in a file was reported as undefined** — one class name accounted for 113 findings by itself. And the hand-written built-in table was missing the entire error hierarchy, so `throw ValueError(...)` read as a call to nothing.

## The Bug Nobody Was Looking For

`Clipboard := text` is v1. In v2 the clipboard is `A_Clipboard`, so that line assigns an ordinary local variable and the copy never happens. The script loads, runs, exits zero, and does nothing. **46 of 159 submissions do this** — clipboard-editor scripts, in a clipboard-editor benchmark, that cannot copy.

Nothing in the stack reported it. `/validate` is happy, the interpreter is happy, and CodeIntel filed all 140 instances as `unused-local` at the bottom of the list, ranked below a TODO comment. It took a nine-line text scan to surface, and it now runs before the parse gate — because it is plain text, it still reports on the 49 files that do not load at all, which never reach Lint or CodeIntel.

Independent confirmation arrived by accident: when the editor's post-edit hook ran one of these scripts, it crashed at runtime on exactly that unassigned `Clipboard`.

The top row is the interesting one. AHK resolves identifiers case-insensitively, so a local named `main` *is* the class `Main`, and the assignment fails with "This Class cannot be used as an output variable." It is the single largest named failure mode in the corpus, and it is a naming convention — not a language feature anyone got wrong.

## What Is Not Built

Tier 2 is pure-function grading, and it costs money per model output, so it stays behind an approved ceiling. Tier 4 needs a machine whose keyboard and mouse can be surrendered for the length of a run.

Tier 3 has a nearer limit worth naming: the shim intercepts input, windows, filesystem and registry, but it does not shadow `Gui()`. **145 of the 159 scripts build a GUI**, so today tier 3 can only fan out over the other 14. That is not a bigger-shim problem — it wants a separate Windows desktop, which is also what tier 4 needs. One piece of plumbing unlocks both halves of the behavioural grading the board does not yet have.

Everything above is syntax and structure. The [repair benchmark](post.html?slug=ahk-repair-benchmark) already showed that visible failures get fixed and silent ones do not; the clipboard result is the same lesson from the other end, where the silent failure was in the measuring instrument.
